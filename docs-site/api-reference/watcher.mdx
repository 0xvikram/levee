## GET /health

Returns 200 when healthy and 503 otherwise.

```json
{ "ok": true, "service": "watcher", "lagMs": 1700, "lastBeat": "ISO" }
```

Healthy means Mirror lag at most 20 s and a successful tick within 20 s. An unhealthy watcher withholds heartbeats, so the gate refuses everything with `no-watcher`.

### BreachView

`{ txId, reason, to?, amount?, kind?, consensusAt, historic? }`. `historic: true` means it was seen while priming on start: reported, not contained.

| Reason | Meaning |
|---|---|
| `no-receipt` | No receipt for this transaction id |
| `receipt-after-movement` | The receipt reached consensus after the movement |
| `receipt-mismatch` | Token, from, to, amount or kind differ |
| `receipt-reused` | The receipt was already used |
| `over-transfer-cap`, `over-daily-cap` | The movement breaks a cap |
| `unknown-destination` | The receiver is not a known recipient |
| `treasury-allowance` | The treasury granted an allowance |

### IncidentOut

```json
{ "v": 1, "type": "incident", "incidentId": "0x…32 bytes", "token": "0.0.x",
  "breaches": [{ "txId": "…", "to": "0.0.x", "amount": "…", "reason": "no-receipt" }],
  "actions": [{ "step": "freezeAccount", "account": "0.0.x", "txId": "…", "ok": true, "atMs": 4845 }],
  "detectedMs": 2865, "containedMs": 6861 }
```

`detectedMs`, `containedMs` and `atMs` are measured from the breach's consensus time. An action on a known partner carries `note: "known partner: frozen, not wiped; admins decide"`. A failed action carries `error`.

## GET /events (SSE)

Replays the last 100 frames.

| Event | Data |
|---|---|
| `matched` | Movement `{ txId, consensusAt, token, from (null for a mint), to, amount, kind }` |
| `breach` | BreachView |
| `detected` | `{ incidentId, breaches, detectedMs }` |
| `plan` | `{ incidentId, steps: [{ step, account?, amount?, why }] }` |
| `step` | `{ incidentId, step, account?, amount?, txId, atMs }` |
| `incident` | IncidentOut |
| `health` | `{ healthy: true, lagMs, heartbeatAt }` or `{ healthy: false, lagMs, lastError }`, every 30 s |

Plan steps are `freezeAccount`, `wipeAndFreeze`, `wipeFrozen`, `burnSupply` and `pauseToken`.
